# Reports

Reports persist the result of a comparison so it can be read later without
re-running it, or consumed by other tools.

- **RPT-001** (P0): Every session type has a "<Type> Report…" command (Session menu)
  and a script command. Folder views also offer "File Compare Report…" for the
  selected pairs, and the folder report can **include links to file reports** (HTML
  side-by-side only), generating one file report per differing pair next to the folder
  report.
- **RPT-002** (P0): Outputs: **Printer** (print preview; colour or mono; portrait or
  landscape; wrap none/character/word), **HTML** file or clipboard (colour, mono, or
  custom external CSS; wrap none/word; self-contained with embedded CSS and, for
  pictures, embedded PNGs), **Plain text** file or clipboard, **XML** (folder and text
  "XML Dump" layouts; documented schema), **Patch** (text).
- **RPT-003** (P0): Common dialog: layout selector, options (per layout), display
  filter mode (All / Differences / Same / None / Context) with the view's current
  filter as default, "Ignore Unimportant", "Just selection" (file views), title,
  output target, "View in Browser" / "Print Preview" buttons; the dialog remembers
  last choices.
- **RPT-004** (P0): Header: title, produced timestamp, mode, filters in effect, left/
  right (and center/output) specs, per-side errors when a side failed to load.

## Layouts per type

| Type | Layouts | Layout-specific options |
|------|---------|-------------------------|
| Folder Compare / Merge / Sync | Side-by-side, Summary, XML Dump | columns (Status, Revision, Version, Size, CRC, Modified, Attributes, Owner, Group; defaults Size + Modified), display filter (all folder filters), include links to file reports; summary = counts per state (same, left/right newer, left/right orphan, difference, conflict, mergeable, uncompared) |
| Text Compare | Side-by-side, Summary, Interleaved, Patch, Statistics, XML Dump | show context, include line numbers, strike-out left/right differences (interleaved), patch style normal/context/unified; statistics = CSV with SourceFile, CompareFile, Total, IAdded/IDeleted/IChanged/IOriginal (important), UAdded/UDeleted/UChanged/UOriginal (unimportant), errors; summary = counts of same/important/unimportant/ignored/orphan lines and sections |
| Text Merge | Summary (statistics by merge class), Interleaved (P2) | |
| Table Compare | Side-by-side, Summary, Interleaved | row numbers, per-sheet sections |
| Hex Compare | Side-by-side, Summary, Interleaved | byte addresses |
| Picture Compare | Side-by-side (images + difference image), Summary | ignore-unimportant |
| Media / Version / Registry | Side-by-side, Summary | |

- **RPT-010** (P0): HTML side-by-side text reports use the same colour semantics as
  the view (important red, unimportant blue, orphan, replacement) with a legend; lines
  hidden by "Differences"/"Context" modes are replaced by "N lines hidden" rows.
- **RPT-011** (P0): Reports are generated by `hikasa-report` from result models and
  are therefore available headless (scripts, CLI) with byte-identical output to the
  GUI.

## M1 reports (binding interpretation; contract §1.7, §3.4; decisions D-18, D-24)

The M1 subset is implemented by `hikasa-report` (`render_text_report`, `render_folder_report`,
`text_compare_json`, `folder_compare_json`); the CLI and the GUI call the same functions (RPT-011). Text
reports: the annotated unified diff (the CLI default), patches in normal, context and unified style, side-by-side
plain text and HTML, the summary (text or HTML) and the statistics CSV. Folder reports: the status list (the CLI
default), side-by-side plain text and HTML, the summary (text or HTML) and the JSON document. XML dumps,
interleaved layouts, printing and links to file reports come later.

**Header (RPT-004).** Every side-by-side and summary report, and every patch, starts with a header:

- the title (default "Text Compare" / "Folder Compare", or the one given with `--title`);
- `Generated: <time> by <generator>`: the generation time in RFC 3339 with the offset of the user's zone
  (`2026-10-21T14:05:00+02:00`) and the program name and version. **D-24:** report code never reads the clock;
  the time is supplied by the caller (the CLI or GUI captures it once), and when none is supplied the line is
  left out (golden tests);
- `Left:` / `Right:` — the specs; for text reports also the encoding (with `BOM` when one was stripped), the
  line-ending style (`lf`, `cr_lf`, `cr`, `mixed`, `none`) and `binary` for binary content, e.g.
  `Left: /a/x.c (UTF-8, lf)`;
- `Mode:` — the display mode and Ignore Unimportant (`display: differences; ignore unimportant: no`); folder
  reports add the folder mode and Suppress Filters. Patches show their own context (`display: context (3 lines)`;
  the normal diff `display: differences`);
- `Rules:` — the rules in effect, in fixed English wording. Text: format, algorithm used (and the one chosen),
  skew, closeness, never-align, the unimportant items, whether line endings are compared, and how orphan lines
  count. Folders: the criteria (`size, timestamps (2 s), content: rules`), the name filters
  (`filters: *.c;-obj\`), other filters and the non-default alignment and handling options;
- `Left error:` / `Right error:` — a side that failed to load (GUI views; CLI reports have none);
- `Status: incomplete (the comparison was cancelled)` for a cancelled folder comparison;
- one `Warning: <code>: <message>` line per warning of the comparison and of the rendering (`patch_lossy_eol`,
  `patch_encoding`, below).

In patches every header line starts with `# `, so that no header text (a title, a path) can be read as patch
syntax; patch programs skip such leading text. The HTML header is an `<h1>` and a table. The statistics CSV, the
folder list (one record per line) and the JSON document have no header. All wording is fixed English; reports
never depend on the locale, the clock or the platform, and identical inputs give byte-identical output
(INV-RPT-1). Text output ends lines with `\n`, the CSV with `\r\n` (RFC 4180).

**Display modes.** `all`, `mismatches` (= differences), `context` and `matches` (= same), also with the script
prefix `display-`. Text: they select rows; every run of hidden rows becomes one "… N lines hidden …" row
(RPT-010). Folders: All → all items with the folder structure; Mismatches → differences, files only; Context →
differences with their folder structure; Matches → same items, files only. Display modes never change the
summary, the statistics or the exit code (D-03); Ignore Unimportant does (TC-024): unimportant rows count as same
for display, the verdict and the patches.

**Patches.** A patch is exact: applied to the left file, it reproduces the right file byte for byte. A row is
written as context only when its two lines are byte-for-byte identical, terminators included; every other row is
written as a deletion and an insertion, whatever the comparison rules ignore. So a line whose ending differs
(line endings are not compared by default, D-04) or a last line that lacks the final newline on one side only is a
change of the patch, even when the comparison calls the two lines the same. Hunks are the clusters of such rows
with N lines of context, and two changes at most 2N lines apart share a hunk (when line endings are compared,
this is exactly the "Context" display). With Ignore Unimportant, the hunks (and normal-diff commands) that hold no
important difference are left out, so such a patch deliberately does not carry them; the rows of the kept hunks
are still written exactly. The tests apply every style, under the default rules and with line endings compared,
to LF, CRLF, lone-CR, mixed-ending, BOM and missing-final-newline files, with an exact applier, GNU patch (no
fuzz) and `git apply`. The annotated unified diff adds ` important` or ` unimportant` after a hunk header, which
patch programs read as the optional section text. File headers carry the spec (C-quoted when it contains a
backslash, a quote or a control character) and the modification time. Lines keep their LF or CRLF terminator; a
line ending in a lone CR, or an artificial break of the characters-per-line limit, is written with LF and the
report warns `patch_lossy_eol` (the patch then reproduces the right file with those endings as LF); a side's last
line without a terminator is followed by `\ No newline at end of file`, which therefore never sits in the middle
of a hunk. Patches are UTF-8 text: the BOM of a UTF-8 file is written back before line 1, so the patch applies to
the bytes; for a file stored in another encoding (windows-1252, UTF-16, …) or decoded lossily, the report warns
`patch_encoding` once for that side (the patch may not apply to its bytes), and also for a file holding nothing
but a BOM, which no line can carry. In a context diff, an empty range after line `l` is written `l+1,l` (patch
programs read a lone number as one line). A patch of identical files is the header only. With ANSI colours (a
terminal view, never applied), the control and bidirectional formatting characters of the content are shown as
escapes, as in the side-by-side report.

**Side-by-side text.** Columns: line number, left text, marker, line number, right text, in `--width` columns
(default 160). Markers: ` ` same, `|` changed, `~` unimportant change (` ` under Ignore Unimportant), `<` left
only, `>` right only. Tabs expand to the format's tab size; widths follow Unicode display widths of whole character
sequences (wide characters take two columns, and so do emoji sequences joined by ZWJ or with a variation
selector; such a cluster never straddles a break); control characters and bidirectional formatting characters
(U+202A–U+202E, U+2066–U+2069, U+200E, U+200F, U+061C) are shown as escapes (`\u{1b}`, `\u{202e}`), so file
content can neither move the cursor nor reorder the row; long lines wrap by character or word, or are cut with
`--wrap none`. Line numbers are the file's: with a characters-per-line limit, the pieces of a long line show
the number of the line they come from. With ANSI colours, important differences are red and unimportant ones
blue.

**Side-by-side HTML (RPT-010).** One self-contained document: an embedded stylesheet (colour, or monochrome with
`html-mono`; a custom stylesheet is embedded after it, so its rules win: it is available through the API,
`HtmlStyle`, for the GUI and scripts, and is not an M1 CLI flag), the header, a legend (important, unimportant,
orphan, replacement, hidden lines), and a table with line numbers, both texts and the marker. Changed rows get a
light red (important) or blue (unimportant) background, the differing text red or blue; orphan rows the orphan
colour; hidden runs one "… N lines hidden …" row. Every text is HTML-escaped, with control and bidirectional
formatting characters shown as escapes; there are no scripts, no external resources and no generated ids. Long
lines wrap by CSS.

**Summary.** Text: the verdict, then rows (same, changed, left only, right only, important, unimportant),
sections (important, unimportant) and the line counts of important and unimportant sections. Folders: the
verdict and completeness, file and folder pairs per state (same, left/right newer, different, left/right only,
unknown, errors, filtered), the files, folders and bytes of each side, and the content-test results.

**Statistics (D-18).** The CSV has the header row
`SourceFile,CompareFile,Total,IAdded,IDeleted,IChanged,IOriginal,UAdded,UDeleted,UChanged,UOriginal,Errors` and
one data row per pair. Counts are per section, by the section's importance (a section is important when any of
its rows is): an added section counts its right lines as *added*, a deleted section its left lines as *deleted*,
a changed section its left lines as *original* and its right lines as *changed* — the `a`/`d`/`c` semantics of
the normal diff. `Total` is the number of rows; `Errors` lists per-side load errors (`left: …; right: …`) or is
empty. Fields containing `,` `"` CR or LF are quoted.

**Folder list.** One line per visible item: a marker, two spaces and the path (`/` after a folder; control and
bidirectional formatting characters escaped as `\n`, `\t`, `\u{…}`, and a backslash as `\\`, so that every
printed path names exactly one item). Markers: `=` same, `>` left newer, `<` right newer, `!` different,
`~` different only through unimportant content differences (same under Ignore Unimportant), `-` left only, `+`
right only, `?` unknown, `E` error, `.` filtered (only with Suppress Filters). The last line counts the files:
`# 120 same, 0 left newer, 1 right newer, 1 different, 1 left only, 1 right only, 0 unknown, 0 errors`; it is
left out when the comparison holds no item at all. It is part of the report on stdout, so `--quiet` (which never
changes stdout) keeps it.

**Folder side-by-side.** Per visible item, indented by depth: the left name and columns, the marker (and the
state in words with the Status column), the right name and columns. Columns: Size (default), Modified (default,
RFC 3339 UTC), Attributes (DOS letters or the Unix permission string), CRC, Owner, Group (numeric ids in M1). A
folder's size is the total of the files below it on that side (FC-040); a name-only entry (an item hidden by a
name mask) and an entry whose metadata could not be read show no size or time, and a folder whose listing failed
on a side shows no size there (its total is unknown). Names are escaped as in the list and measured by their
display width (emoji sequences included), so the columns stay aligned; flatten mode shows each side's folder
before the name; unfollowed symbolic links show `-> target`. The HTML table colours each side with the FC-031
colours (black same, red newer/different, purple orphan, grey older or unknown, teal filtered, the error colour)
and has a legend.

**Folder JSON (D-29).** The JSON report is the `hikasa.folder_compare.v1` result of `folder compare --json` with
`"schema": "hikasa.folder_compare.v1"` as its first key (under `--json` the envelope carries the schema and its
`result` is the same document without the key): a flat, pre-order list of the visible items with `path` and
`depth` (no nested objects, node ids never printed), the statistics and verdict, the display options and the
rules. The rules are written in full: absent optional values are `null`, never left out (unlike the TOML rules
file). Arrays are never `null`; likewise `display.toggles` of `text compare --json` always lists the shown
categories (`[]` for none).
